Option 2 — the contextual return, once it moves down to the page

You're right that the duplication isn't universal. "← Games" duplicates a nav item; "← Astros @ Cubs" does not. So the return isn't removed — it's filtered. The nav owns the five sections; the return owns the one thing you came from. That single distinction resolves every case below, and it also decides which nav item gets the rust underline on pages that belong to no section.

The rule
Render the return only when the screen you came from is an instance — a game, a team, a player. If it's one of the five nav destinations, the nav item already is the return.
  • The label is the thing's name, never the word "Back" — "← Astros @ Cubs", "← Houston Astros", "← Jeremy Peña". A named return is the only kind worth 15px of the page block.
  • One hop, never a trail. Teams → Astros → Peña shows "← Houston Astros" and stops. No breadcrumb chain; the nav covers the top of every path.
  • Cold arrival = no return. Direct link, refresh, or a jump out of search has no instance behind it. Don't synthesise a parent — a player legitimately sits under a game, a team and a leaderboard, so any guess would be a lie.
  • Derive it from history, not from the screen. Today's mocks hardcode back="Games" per screen; the ported version reads the previous route. A game view entered from a player page returns to that player.
  • No reserved space. Presence is fixed for the life of a visit, so letting the h1 sit 33px higher when there's no return costs nothing — nothing moves while you're looking at it.

One open edgeworth a decision before porting
Deep chain

Games → game → player → that player's other team page → a player on it. One hop back means the return at step 5 names step 4, and step 1 is only reachable via the nav's Games item — which is fine, because Games is a list you can re-enter, not a state you lose. But if you had paged the landing date ("Yesterday's games") and then dived three screens deep, the nav item drops you back on today. Either the date survives in the route, or a deep return to the landing page is a genuine loss. I'd put the date in the URL and treat that as closed.

Port shape: BrandHeader loses back/onBack entirely and gains active for the horizontal nav; PageTitle gains one optional returnTo={{label, href}}, supplied by the router from the previous route and omitted whenever that route is one of the five destinations. The filter lives in one place, so no screen can get it wrong on its own.
