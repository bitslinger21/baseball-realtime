Header nav — horizontal, instead of the hamburger

Five destinations is few enough to show. The drawer was sized for a nav that could grow; it didn’t. What each option really decides is where the contextual return goes — “← Games” and a Games nav item are the same destination, so putting both in one row says the same thing twice. The return is drawn here at its real size: BrandHeader in shared.jsx renders it 21px / 600 / ink. (The team page’s hand-built copy uses a quiet 13px grey — the two disagree, and these frames assume the component, since that is what every non-team screen mounts.)

Everything in one row, nothing hidden, and the rust underline lands on the bar’s hairline — the same idiom as the Overview / Schedule tabs below. The cost is visible above: Games sits four items away from ← Games, the same link twice in one bar — and at the return’s real weight (21px ink, from BrandHeader) it is the loudest thing in the row, announcing a destination that also sits quietly four items to its left. Settings also reads as a peer of Teams and Standings, which it isn’t — one is a preference screen, the others are the content of the app.

The header becomes purely global — where you can go — and the return becomes purely local: where you came from, sitting with the page it belongs to. That kills the duplicate outright, and the four remaining nav items are all content, with Settings dropped to a gear beside search. Two honest costs. The return drops from 21px ink in a fixed screen position to 15px muted in the page block — a real demotion, not a nudge, and that size is a judgement call here rather than an existing value; and it now stacks above the left-anchored Overview / Schedule tabs, so the left edge carries a return, a hero and a tab strip in three tiers. The gear is a net-new glyph — nothing in the project draws one today.

Dropping the return fixes the duplication, and pulling Settings out of the list leaves four content destinations. But look at row 2: it now holds two icons and ~1180px of empty cream. A row that exists to carry 80px of content is the most expensive way to place it, and the active-item underline still has no hairline to sit on. Same two rows you drew, in the other order — and that order is what makes it work. Nav sits on the bar’s bottom hairline, so the rust underline returns and the global nav reads as the same idiom as the tab strips beneath it. The wordmark keeps a row to itself with the utilities it belongs with. Cost is the one option 3 had: 97px of chrome before the page (against 63px for a single row), which is felt most on the game view.

My read, updated: if you want two rows, make it option 5, not 4 — the icons don’t justify a row of their own, and putting nav on the bottom row is what earns back the active-state underline. Between 5 and 2 it’s a straight trade: 5 gives the nav more presence and a cleaner brand row, 2 keeps the header to 63px. On the game view — sticky line-score bar, live feed — I’d still take the shorter one.
